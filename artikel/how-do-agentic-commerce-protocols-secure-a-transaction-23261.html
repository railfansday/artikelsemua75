An agentic commerce protocol is a defined set of rules and interfaces that let AI agents discover, authorize, pay for, and track commercial transactions in a machine-verifiable way. The security question is not "can agents act?" — it is "how do we know the right agent acted, within the right limits, for the right purpose, and that the outcome can be verified afterward?". According to recent reports, A plant's procurement agent ordered a replacement filter. Payment succeeded — USDC moved from buyer to seller via x402. Then the agent's process times out and dies. The buyer later disputes the shipment: the part number is right, but the filtration rating is wrong. (Related: Latest Update: Two weeks later, Senate vote count is co...)

Recent findings suggest that this is the case that separates agentic commerce security from ordinary payment security. The payment was authorized. The money moved. The dispute is about fulfillment.

Sources indicate that A payment receipt proves a transfer occurred — amount, asset, sender, recipient, hash. It is not evidence of fulfillment. A signature proves who signed, not that the claims are true. A hash proves a file wasn't altered, not that its contents are accurate. An EAS attestation anchors a claim on-chain; it does not independently establish that the physical event occurred. A transaction submission proves an attempt, not settlement.

These are not interchangeable. Confusing them is how agentic commerce vulnerabilities happen.

According to recent reports, MCP connects agents to tools; A2A connects agents to agents; AP2 authorizes agent payments; x402 executes machine-native payments; ACP defines agentic checkout; EAS anchors evidence. SAAX is designed to complement these — recording the durable commitment, evidence trail, dispute lifecycle, and settlement authorization around them. It is not a replacement for any of them.

See the SAAX status page: immediate x402 payments on Base mainnet; escrow testnet-only; Financial Recovery Engine custody candidates local-only; no independent audit completed. The specification and conformance suite document the commitment lifecycle, evidence interface, authorization model, and settlement linkage.
