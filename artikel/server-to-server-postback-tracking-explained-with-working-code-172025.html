Sources indicate that if you've ever integrated an affiliate network, an ad platform or a partner program, you've met the postback URL. It's a plain HTTP call, but small mistakes in how you send it lead to missing conversions, double payouts and long email threads with partners.

This post walks through the whole flow with code you can copy: where the click ID comes from, how to send the postback from your server, how to make it safe to retry, and how to receive one on the other side.

The tracker appends the click ID to your landing page URL. Your only job is not to lose it. The most reliable place is the server: read it on the first request and store it with the session, then with the user or order.

Validate the format before storing it. The value comes from a URL, so treat it like any other user input.

URLSearchParams takes care of encoding. Building the query string by concatenation is the most common source of broken postbacks: an & or # inside an order ID silently cuts the URL. (Related: Industry News: Simple considerations for simple people ...)

In production, don't call this inside the checkout request. Put it in a job queue (or an outbox table) so a slow tracker never slows down your checkout, and so retries survive a restart.
