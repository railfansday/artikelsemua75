Steadfast is a new Ruby project that aims to provide a new way to dynamically generate Ruby code at runtime by synthesizing and manipulating ASTs, as an alternative to the common technique of calling eval with a dynamically generated string containing Ruby source code.

In the last Steadfast update I discussed the foundations of the project, its general API design, and my work on implementing the basic capacity of turning ASTs back to source code (using Steadfast.to_source), as well as providing some facilities for translating backtrace locations for code derived from AST that were composed of pieces of code from different locations. Over the last few days, I’ve concentrated on implementing the ability to transform an existing AST by replacing specific nodes therein. Previously, I called this “mutating” an AST, but actually I realized this term might be confusing, since Prism ASTs are inherently immutable, that is, they cannot be modified. Instead, you need to create a copy of an AST node with the requisite changes, so using the verb “mutate” is in fact incorrect. So henceforth I’ll use the term “rewrite” instead, which seems more fitting, since we’re basically taking existing code and rewriting it. So, if we want to rewrite a given node, we can’t just create a copy of it with its plain value attributes changed. For example, if we have a method call foo, which we want to change to bar, we can’t just rewrite the corresponding CallNode with a modified name attribute, because the location attribute for this (called message_loc) will still point to the original source code containing the string foo. We actually need to replace the CallNode with a another CallNode that actually represents a call to bar.

As you can see, this is not very convenient. We need to reach into the AST to extract the body of the lambda, which is a StatementsNode, and we then need to inject the replacement method call into it. Once the body is rewritten, we need to create a copy of the lambda node itself, so it will point to the new body.

In the above example, we just needed to touch the body node, which is a subnode of the lambda root node, but in other cases we might need to drill down and make changes to some subnodes that are nested a lot deeper in the AST, which means that for any node that was replaced, we also need to replace all its parent nodes.

In a recent development, so this is what I set out to solve with Steadfast.rewrite. The implementation is quite simple: for any modification (rewrite) of a subnode, we automatically create modified copies of all its parent right up to the root. That’s why Steadfast.rewrite trakes an AST as its first argument, and returns a rewritten AST as its return value.

It has been revealed that in the rewriter block, we filter out anything that is not a call to >> (since in Ruby, binary operators are actually method calls). We then extract the call_node to the right of the >> operator (its argument), and replace the operator call with this call node, with its arguments rewritten so as to inject the value to the left of the operator into the call.

In a recent development, notice how we recursively call Steadfast.rewrite(n.receiver, &r). In order to make it possible for us to recurse inside the block, Steadfast.rewrite yields, along with the node, a reference to the block itself, which lets us call Steadfast.rewrite recursively with the same block. This technique is interesting in and of itself, and is quite useful as you can see, since working with ASTs is inherently recursive.

Pipe operator syntax transformation and tail call optimization are but two possible applications of AST rewriting, but Steadfast.rewrite can also be used for inlining method calls, and more generally, for such things as wrapping code in a loop, or in a begin/rescue block, unrolling loops, injecting arguments into method calls… the possibilities are endless!

In the upcoming stages of this project, I’ll use Steadfast.rewrite to implement the code quoting tool (aka quote/unquote), as well as for synthesizing different kinds of AST nodes.
