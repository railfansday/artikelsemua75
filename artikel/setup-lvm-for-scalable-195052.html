📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Industry observers note that haii, pada postingan ini saya ingin sharing study case, dimana saya punya server dengan ukuran 3725.5 GB. Dengan 1 disk dan kapasitas tersebut saya memutuskan Raid0 lalu membuat LVM untuk penyimpanan data dan scalablenya, untuk tabel partisinya kira-kira seperti ini.

Saat pertama kali install server dalam kasus ini Ubuntu 26.04 LTS pada bagian pemartisian pilih custom dan setting agar OS tidak berjalan pada LVM.

Industry observers note that kita asumsikan OS sudah terinstall dan anggap kita pakai user root, langsung kita masuk ke tahap setup sisa partisi jadi lvm. Perlu diketahui server ini akan saya jalankan service docker dan mysql dimana nanti partisi /var/lib/docker dan /var/lib/mysql adalah bind mount dari LVM. Pastikan dahulu tabel partisi dan ruang kosong.

cek dengan lsblk jika belum ke load lakukan refresh partisi.

Buat Physial Volume dari partisi yang tadi kita buat di /dev/sda4 dan verifikasi dengan pvs.

Kemudaian buat Volume Group dan verifikasi vgs.

Lalu baru kita buat Logical Volume, Jika ingin seluruh kapasitas dialokasikan untuk satu logical volume gunakan 100%FREE. Best practicenya disisakan sedikit untuk scalable biasanya 95% - 98%. Tapi pada case ini saya pakai full 100% kapasitas. Gunakan lvs untuk verifikasi.

Format partisi lvm kita agar bisa di mounting dan siap pakai, sesuai best practice kebutuhan saya memilih filesystem ext4. (Related: Few-shot learning in practice: GPT-Neo and the 🤗 Accele...)

Sesuai kebutuhan service saya ingin satu pool yang dipakai bersama tanpa dibagi, dan itu bisa dicapai lebih aman dengan satu LV dimount ke /mnt/data, lalu hanya Docker dan MySQL yang diarahkan ke sana.

It has been revealed that setelah itu install Docker dan MySQL seperti biasa. Keduanya otomatis menulis ke LVM lewat path default, jadi tidak perlu ubah konfigurasi.
