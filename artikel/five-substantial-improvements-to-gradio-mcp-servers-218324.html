Recent findings suggest that gradio is an open-source Python package for creating AI-powered web applications. Gradio is compliant with the MCP server protocol and powers thousands of MCP servers hosted on Hugging Face Spaces. The Gradio team is betting significant on Gradio and Spaces being the best way to build and host AI-powered MCP servers.

To that end, here are some of the massive improvements we've added to Gradio MCP servers as of version 5.38.0. (Related: Tech Report: Rockstar explains why GTA 6 added its Crim...)

If you've tried to use a remote Gradio MCP server that takes a file as input (image, video, audio), you've probably encountered this error:.

This happens because the Gradio server is hosted on a different machine, meaning any input files must be accessible via a public URL so they can be downloaded remotely. (Related: How Much Latency Does a Self-Hosted LLM Gateway Add? La...)

While many ways exist to host files online, they all add a manual step to your workflow. In the age of LLM agents, shouldn't we expect them to handle this for you?

It has been revealed that gradio now includes a "File Upload" MCP server that agents can use to upload files directly to your Gradio application. If any tools in your Gradio MCP server require file inputs, the connection documentation will now show you how to start the "File Upload" MCP server:.

Learn more about using this server (and notable security considerations) in the Gradio Guides.

Sources indicate that depending on the AI task, getting results can take some time. Now, Gradio streams progress notifications to your MCP client, allowing you to monitor the status in real-time!

In a recent development, as an MCP developer, it's highly recommended to implement your MCP tools to emit these progress statuses. Our guide demonstrates you how.

Recent findings suggest that if you want to integrate an existing backend API into an LLM, you have to manually map API endpoints to MCP tools. This can be a time-consuming and error prone chore. With this release, Gradio can automate the entire process for you! With a single line of code, you can integrate your business backend into any MCP-compatible LLM.

In a recent development, openAPI is a widely adopted standard for describing RESTful APIs in a machine-readable format, typically as a JSON file. Gradio now features the gr.load_openapi function, which creates a Gradio application directly from an OpenAPI schema. You can then launch the app with mcp_server=True to automatically create an MCP server for your API!

Find more details in the Gradio Guides.

It has been revealed that A common pattern in MCP server development is to use authentication headers to call services on behalf of your people. As an MCP server developer, you want to clearly communicate to your users which credentials they need to provide for proper server usage.

Sources indicate that to make this possible, you can now type your MCP server arguments as gr.Header. Gradio will automatically extract that header from the incoming request (if it exists) and pass it to your function. The benefit of using gr.Header is that the MCP connection docs will automatically display the headers you need to supply when connecting to the server!

In the example below, the X-API-Token header is extracted from the incoming request and passed in as the x_api_token argument to make_api_request_on_behalf_of_user.

You can read more about this in the Gradio Guides.

Recent findings suggest that gradio automatically generates tool descriptions from your function names and docstrings. Now you can customize the tool description even further with the api_description parameter. In this example, the tool description will read "Apply a sepia filter to any image.".
