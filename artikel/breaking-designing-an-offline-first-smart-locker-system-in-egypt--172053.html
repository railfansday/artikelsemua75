We are right now architecting the software and hardware pipeline for a connected Smart Locker System in Egypt, designed for last-mile logistics and automated parcel pickup across commercial hubs and residential compounds.

In our environment, one of the biggest engineering hurdles is dealing with intermittent 4G/LTE connectivity at outdoor physical locker terminals. If a customer arrives to collect a package using an OTP or QR code, the locker door must reliably unlock even if cloud connectivity drops for 30–60 seconds. Our Current Architecture: Edge Controller: Raspberry Pi CM4 / ESP32 communicating with RS485 relay boards to trigger 12V solenoid locks. Client Interaction: 7-inch touch screen running an Electron / Flutter kiosk app, with barcode scanner & keypad. Backend Cloud: Node.js / Go microservices hosted on AWS with PostgreSQL and Redis. The Dilemmas We’re Facing: Sync Protocol: Should we rely on an MQTT broker with QoS 1/2 with local edge buffering (SQLite / Redis on edge), or use persistent WebSockets with an offline-first caching layer? Offline Verification: How do you securely handle localized validation of one-time PINs (e.g., HMAC-based time-synced tokens vs. pre-cached hashed drop-off manifests) without opening up replay attack vulnerabilities?
