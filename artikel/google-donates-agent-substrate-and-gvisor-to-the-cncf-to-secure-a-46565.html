Google has declared it is donating Agent Substrate and gVisor to the Cloud Native Computing Foundation (CNCF), placing two notable components of its AI agent infrastructure under vendor-neutral open-source governance. The move is intended to address two emerging challenges in running autonomous agents at scale: securely executing untrusted, AI-generated code and managing the substantial compute overhead created by agents that frequently pause and resume. In a recent development, the announcement also includes OpenRL, Google's open-source reinforcement learning orchestration project. Together, the projects target different layers of agent infrastructure, from isolated code execution to managing agent lifecycles and coordinating large-scale training workloads. The goal is to establish an open foundation for agentic applications, much as Kubernetes helped standardise container orchestration. (Related: How to generate text: using different decoding methods ...)

Google argues that conventional Kubernetes workloads and AI agents have fundamentally different execution patterns.

A traditional application typically starts, serves requests, and continues running. An AI agent, however, may execute a tool or code for a few seconds before waiting for model inference, an external API, or human approval. Google estimates that agents can spend 90-95% of their time idle while still holding notable state, including memory, files, repositories, and active sessions.

Keeping every agent in a dedicated Pod wastes resources, while scaling to zero introduces delays when environments must be reconstructed. At the other extreme, large-scale agent evaluations can overwhelm Kubernetes control planes when thousands of short-lived execution environments are repeatedly created and destroyed.

Google developed Agent Substrate to address these limitations by separating agent state (actors) from the compute resources (workers) used to execute it.

In a recent development, actors represent individual agent sessions and retain their state, including filesystem contents, memory, and execution context. Workers provide reusable, pre-warmed execution environments drawn from shared Kubernetes pools.

When an agent needs to resume, Substrate assigns it to an available Worker and restores its previous state. When the agent becomes idle, its state can be saved and the underlying compute resource released.

Recent findings suggest that according to Google, this approach lets agents resume in under 500 milliseconds without creating a new Kubernetes Pod for every execution. It also reduces pressure on the Kubernetes control plane by managing agent lifecycles independently of individual Pod objects.

Recent findings suggest that the second major challenge is security. AI agents routinely execute generated shell commands, install packages, and interact with external tools. Treating this code as trusted creates significant risks, particularly when multiple agents share infrastructure.

Sources indicate that google's gVisor provides an additional isolation boundary through a user-space application kernel. Instead of letting containerised applications interact directly with the host Linux kernel, gVisor intercepts system calls and handles them within its own isolated environment.

This reduces the exposure of the underlying host while retaining much of the efficiency associated with container-based execution.

Agent Substrate also supports Cloud Hypervisor microVMs for workloads requiring hardware-level virtualisation. This gives platform teams flexibility to select an appropriate isolation boundary without changing the overall agent lifecycle model.

According to recent reports, the announcement reflects a broader shift in cloud-native infrastructure. Kubernetes was designed around long-running applications and relatively stable workloads. Agentic systems introduce more dynamic execution patterns, where environments must be created, suspended, restored, and isolated at much greater frequency.

Recent findings suggest that other providers are addressing similar challenges through technologies such as Kata Containers, Firecracker, and dedicated sandboxing platforms. Google's contribution is to combine secure execution with an agent-aware orchestration model and place the resulting technologies within an open ecosystem.

It has been revealed that the wider implication is that AI agents need more than an orchestration framework and access to tools; they need their own secure, stateful, and efficiently managed execution infrastructure. By donating these projects to the CNCF, Google is helping establish the foundations for that next layer of cloud-native computing.
