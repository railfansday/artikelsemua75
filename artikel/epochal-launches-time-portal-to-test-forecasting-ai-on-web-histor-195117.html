Epochal Launches Time Portal to Test Forecasting AI on Web History

According to recent reports, epochal, a upcoming AI company, introduced itself on November 24, 2026 with Time Portal, a point-in-time web environment for AI agents. The company says the archive spans more than 1 trillion pages and is designed to teach systems to forecast without exposing future outcomes.

Recent findings suggest that the announced team includes Guodong Zhang, Zihang Dai and Manuel Kroiss, key members of xAI’s founding team, alongside Alex Bocharoff and Frank Luan. Time Portal, Epochal’s first product, was built in 90 days.

According to recent reports, the tech giant’s premise is that today’s models absorb the internet with many outcomes already visible, whereas people learn by making decisions before knowing the results. Epochal wants agents to rehearse that process across thousands of historical days, using the web as it existed at each selected moment rather than as a single training corpus filled with hindsight. Epochal reports that Time Portal tracks more than 7 trillion URLs across over 30 years of internet history, with minute-level version granularity on the most dynamic pages. Its three components have distinct jobs: search finds historically available pages, fetch retrieves a specific URL, and sandbox supplies a Linux environment gated to the same instant. (Related: Hyperparameter Search with Transformers and Ray Tune...)

Recent findings suggest that the sandbox addresses ways an agent could notice the simulation without reading a future page. Its system clock is set to the chosen instant, while the Ubuntu version, system libraries, language runtimes and command-line tools match that period. Package mirrors and network requests also respect the cutoff, placing commands and web browsing inside the same historical environment.

To assess how closely the simulation matches live deployment, Epochal ran forecasting agents on 347 live questions from prediction markets Kalshi and Polymarket. A few weeks later, it replayed those questions through Time Portal with each cutoff set to the original forecast time. Separate replays gave agents either the live web or no web access.

According to recent reports, in Epochal’s own evaluation, the correlation between Time Portal replay errors and original live forecast errors was 0.98, compared with 0.16 for live-web replays after resolution and 0.49 without web access. The Time Portal replays demonstrated no significant deviations in predictions from the historical runs. Live-web agents could look up resolved outcomes, reducing errors to nearly zero, while no-web errors were larger and only loosely tracked the originals. The experiment therefore measures historical fidelity: how closely a replay matches the original run.

An engineering post describes a strict retrieval rule: fetch returns the newest capture at or before the requested instant and returns a miss if none exists. A later snapshot is never substituted because even the closest future copy could reveal information that was unavailable at the time. The engine also marks disappeared pages as absent, collapses duplicate content within and across URLs, and adjusts ranking as the meanings of terms and facts change.

Developers can start with a limited version for free through the API, console playground or SDKs. The API documentation states the playground does not require an API key, while API calls use an Epochal key and an Accept-Datetime header containing a past timestamp. Python and Rust clients, a command-line interface and an MCP server are also provided. When a sandbox stops, its filesystem and command output are discarded.

Industry observers note that for Epochal, Time Portal is infrastructure for a broader effort to train AI through decisions and observed outcomes rather than static historical text. Its archive and strict cutoffs address how forecasting experiments can be staged without hindsight. Whether work in these reconstructed pasts produces better predictions on unresolved events is the central question for the manufacturer’s approach.
