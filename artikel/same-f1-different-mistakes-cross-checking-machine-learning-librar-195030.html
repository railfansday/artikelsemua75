Industry observers note that on Wine, DIY AutoML and AutoGluon had the same macro F1 and confusion matrix. They misclassified different rows. I used Iris and Wine to look at what the aggregate score leaves out, first by comparing neural-network probabilities and then by scoring separately selected models on the same holdouts. Japanese original.

I used TensorFlow 2.20.0 and PyTorch 2.14.0 on a Windows CPU with Python 3.13.17. Both networks had hidden layers of 32, 16, and 8 units. They shared the standardization fitted on the training rows, Float32 inputs, initial weights, and minibatch order. I ran three training seeds. When both libraries used the same weights for inference, the largest absolute difference in predicted probabilities on the 0–1 scale was about 6 × 10⁻⁸. Experiment settings and reproduction steps. After training each implementation separately, the predicted labels matched row for row on the holdout for all three seeds. The confusion matrices and macro F1 also matched. The probabilities showed small differences. (Related: Block Sparse Matrices for Smaller and Faster Language M...)

According to recent reports, for Iris at seed 42, both models predicted class 2 for CSV line 58, counting the header as line 1. TensorFlow assigned class 2 a probability of 56.867% and PyTorch assigned 53.814%. The correct class was 1, to which they assigned 42.232% and 45.253%, respectively. The confusion matrix records the same error either way.

Log loss reflects the probability assigned to the correct class. For Wine, I kept the fitted models fixed and drew paired samples with replacement from the 36 holdout rows. For each sample I calculated the difference in mean log loss across the three seeds (PyTorch minus TensorFlow). When the number of draws increased from 1,000 to 20,000, the upper end of the 95% interval moved from −3.0 × 10⁻⁷ to +1.8 × 10⁻⁷. With the longer run, the interval just included zero. I left the direction of the difference unresolved. Log loss definition · Recomputing the interval from saved predictions (Japanese).

Sources indicate that autoGluon Tabular 1.6.3 reused the cross-validation and final test row indices saved by DIY AutoML's rank-sl command. Each workflow kept its own candidates and preprocessing. AutoGluon's five candidates in this run were random forest, Extra Trees, k-nearest neighbors, logistic regression, and a weighted ensemble. An available-memory check led to skipping LightGBM on this PC.

Each workflow selected its leader using macro F1 on the shared cross-validation splits. DIY AutoML selected an SVM for both datasets. AutoGluon selected k-nearest neighbors for Iris and logistic regression for Wine. I then scored the winners on the same final test rows. AutoGluon experiment and reproduction steps.

Industry observers note that the paired bootstrap held the fitted models fixed and drew the same held-out rows for both models, within classes, 1,000 times. Both intervals included zero. On Wine, the macro F1 and confusion matrices matched, but the error occurred on CSV line 132 for DIY AutoML and line 136 for AutoGluon, counting the header as line 1.

On the same Windows PC, I ran H2O AutoML 3.46.0.12 with Python 3.14.7 and Java 17. The run used up to five candidates from generalized linear models, distributed random forests, and gradient boosting. H2O used the first of DIY AutoML's saved five-fold repeats and selected by mean fold macro F1. The DIY AutoML models in the comparison came from the original five repeats. H2O selected a generalized linear model on both datasets. H2O configuration and reproduction steps.

Industry observers note that autoGluon and H2O each got all 30 Iris rows right. On Wine, DIY AutoML got 35 of 36 right and H2O got 34. The H2O differences were evaluated using the same resampled test rows as the AutoGluon comparison. Both intervals included zero under this evaluation.
