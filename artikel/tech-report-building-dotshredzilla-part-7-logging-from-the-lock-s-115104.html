Part 6 ended with version 1.6.0 in Play review: no forced ads, Pro for life, and ad hours a server can trust. Version 1.7.0 came from the same place as every other release, a training session.

It has been revealed that between sets my phone is in my pocket or on the bench, locked. Unlocking it with chalk on my hands to tap "Log set" got old fast. So the biggest feature of 1.7.0 doesn't live in the app at all. It lives in the notification shade.

DotShredzilla is an Android workout tracker from FreeRave (DotSuite), written in Kotlin with Jetpack Compose and Firebase, and open source under Apache License 2.0: github.com/kareem2099/Shredzilla.

Recent findings suggest that when a workout starts, a notification shows what you're doing and what comes next, on the lock screen too. Its buttons cover most of a workout:.

Sources indicate that the timer in the notification is the system's, not mine. The notification is posted once with a target time, and Android draws the clock. It counts up the workout time and counts down the rest:. (Related: Porting fairseq wmt19 translation system to transformer...)

According to recent reports, VISIBILITY_PUBLIC is what makes the buttons usable without unlocking. That's a choice worth making on purpose: the lock screen shows the list, the exercise and your last set, and nothing else from your account.

In a recent development, the reply box gets whatever the keyboard sends. On my phone that can be Arabic-Indic digits (٩ ٨) or a decimal comma, so the parser normalizes first, then counts the numbers:.

It has been revealed that one number means reps at the same load. Two numbers mean load and reps, and the load follows the last set's kind: plates stay plates, and a per-side machine doubles what you typed. Anything else gets a short "Try 8, or 9 8" message instead of a wrong set. (Related: The Age of Machine Learning As Code Has Arrived...)

It has been revealed that buttons on a notification go to a BroadcastReceiver, and a receiver isn't allowed to open screens. So Finish is a normal tap target that opens the app on the workout summary, not a background action.

The receiver also needs the running workout. If Android has killed the app in the meantime, the buttons say "Open DotShredzilla to continue your workout" rather than logging a set into nothing. Tapping the notification itself brings the workout back.

Detailed and Compact are free. Rest focus puts the countdown first, and Progress bar uses NotificationCompat.ProgressStyle with a segment per exercise. On Android 16 it also asks to be promoted, which turns it into a Live Update chip in the status bar:.

In a recent development, 1.7.0 also added the first notifications that aren't about a workout in progress. Every one of them is judged against your own training, not a fixed schedule:.

The permission isn't requested on first launch. It's requested on your first rest, the moment a notification is obviously useful. Quiet hours (10 PM to 8 AM by default) hold everything back, and each kind has its own switch.

The rules themselves are plain functions that take a snapshot of your training and return what's due today. A WorkManager job runs them in the background, and unit tests cover the edges, like a deload week that shouldn't trigger a weekly goal alert.

Pro is the layer that interprets your data. Badges are motivation, and motivation shouldn't be paywalled. So all 36 are free: milestones, training, strength, consistency, body and community.

Two lessons from earlier parts revealed up again:.

Industry observers note that badges earned before the feature existed are saved quietly. The first launch after the upgrade would otherwise have shown a stack of banners for things you did months ago. After that, each new badge gets its own banner.

My favorite one is Pocket logger: log a set from the notification.

Industry observers note that event badges come from Remote Config. A JSON list in badge_events defines a title, a window and a goal ("train 3 times this week"), so an event can start without an app update. A broken entry is skipped instead of breaking the badges page, and an earned event badge stays on the account after the event ends.

Version 1.7.1 gives out numbers instead, #1 to #100, from a Cloud Function in a Firestore transaction:.

Recent findings suggest that the number lives in founders/{uid}, which its member can read and nobody can write from the app. I first wanted to put it in the profile document, but version 1.6.0 creates email accounts with a plain set(), which replaces the whole document. A field there could be wiped by an app version that's still installed. A separate document no app version ever writes is safer than any rule about fields.

Since then the function has moved from "account created" to "onboarding finished", so a sign-up someone abandons halfway doesn't take one of the hundred numbers.

The worst bug of this release was simple to describe: on some installs, the app forgot the sign-in every time it closed. Sign in, close, open: signed out.

In a recent development, the cause was Android's Auto Backup. Firebase Auth stores the signed-in user encrypted, with a key from the Android Keystore. Auto Backup happily restored Firebase's files to the latest install, including the encrypted keyset. The Keystore key that opens it never leaves the device, by design. So Firebase found a keyset it couldn't use, couldn't save any sign-in with it, and every launch started signed out.

According to recent reports, the fix has two halves. Latest backups leave those files out, in both rule files, because Android 12 and later read data_extraction_rules.xml and older versions read backup_rules.xml:.

Phones that already restored a broken keyset needed more. At startup, if no sign-in is saved, the old keyset protects nothing, so it's removed before Firebase Auth starts and Firebase creates a working one on the next sign-in:.

Recent findings suggest that while I was in there, I removed a second way to get signed out. The app used to sign out when the profile couldn't be loaded, which on a weak gym connection happened often. Now only an account that was deleted or disabled is signed out. Anything else opens the app and syncs later.

1.7.0 had already been approved by Play. I never published it, and shipped 1.7.1 with the fix instead.

Recent findings suggest that version 1.7.1 is live on Google Play. Next, DotShredzilla learns five languages, including right-to-left Arabic.
