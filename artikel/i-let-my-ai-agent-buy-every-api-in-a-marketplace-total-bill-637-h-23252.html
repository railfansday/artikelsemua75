Two weeks ago I gave my agent a strange mission: buy one call of every endpoint in the x402 ecosystem that wasn't indexed yet on the Bazaar — the discovery layer where agents find pay-per-call APIs.

According to recent reports, not to use the data. Just so the marketplace would notice the services exist. (Related: What I do every time I get an IRS notice...)

In x402, discovery has a chicken-and-egg problem. The Bazaar indexes services that agents actually call — traffic through the facilitator is what gets you listed. So a brand-new API with zero callers stays invisible, and invisible means zero callers, forever.

According to recent reports, we run a catalog of ~220 endpoints (crypto briefs, French manufacturer KYB, rail itineraries, restaurant hygiene data for 1,200+ cities, dev tools for LLM agents). About 83 were indexed when we started. My agent was told: fill the gap.

It worked through the list in batches over a few evenings:.

Recent findings suggest that total: ~6.37 USDC on Base. That bought settlement events for roughly 160 endpoints. Final wallet balance: 13.09 USDC.

Compare that with listing on any traditional API marketplace: submissions, reviews, weeks of waiting. Here, the agent bootstrapped the catalog's own discoverability for the price of a coffee. (Related: Latest Update: Two weeks later, Senate vote count is co...)

Honest section. Three endpoints stayed unindexed because their upstream data source (the French national railway API, fittingly) was having a bad night — 502s all evening. The agent logged them and scheduled a retry. Agents don't get frustrated; they reschedule.

Recent findings suggest that also: my earlier posts an expired API key burned my budget got some pushback about agents paying unsupervised. This experiment is my answer — the guardrails (separate buyer wallet, per-call max spend, hard-blocked merchant wallet) are what made an unattended $6 spending spree safe.

In a recent development, the whole thing ran on a few hundred lines of Node.js: fetch the official catalog, diff against the Bazaar index, attempt a purchase per missing endpoint, log results. The boring part wasn't the payments — those took seconds each. It was figuring out each API's query format with no docs but the 400-error messages themselves.

It has been revealed that the catalog this describes is live; if your agent wants to try pay-per-call without keys, x402 + USDC on Base is genuinely a 20-minute integration. Questions welcome in the comments — I answer them with my agents, obviously.
