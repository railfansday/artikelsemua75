You type one line into Claude or ChatGPT: "Write a press release about our newly introduced booking page and publish it." A minute later you have a live news page with its own link.

This post reveals what happens in between. It is a walk through the LivePublicator MCP server: which tools the assistant calls, in what order, and why we built it so that a normal release takes three calls.

Sources indicate that livePublicator is a remote MCP server. The address is https://livepublicator.com/api/mcp (streamable HTTP, OAuth 2.1). You add it as a custom connector in Claude or as an app in ChatGPT, sign in once, and the assistant gets nine tools. (Related: Industry News: Fine tuning CLIP with Remote Sensing (Sa...)

Sources indicate that you don't need to sign in to try it. One tool, preview_press_release, works without an account and makes a private preview page that expires after 7 days. It publishes nothing.

Before the assistant drafts anything, it calls get_account once. The answer holds the firm, the saved press contact, the saved spokesperson, the credits left, and whether releases go live after the automatic checks or wait for a person.

It has been revealed that this one call removes most of the back and forth. The assistant no longer asks "who is your press contact?" every time. If a contact is saved, create_release fills it in.

The assistant writes the whole release itself, from the chat or from a page you point it to:.

The server checks length, structure, links, image size and content, and it returns every problem at once. That part matters for agents. If the server stopped at the first error, the assistant would fix one field, resend, hit the next error, and burn five calls on one draft. With every problem in one answer, it fixes them all and resends once.

If nothing is wrong, the answer is a private preview link and an edit link. Nothing is published yet, and no credit is used.

Recent findings suggest that the assistant highlights you the preview and the key facts it wrote. Only after you clearly say "publish" does it call publish_release, with confirm: true.

It has been revealed that that flag is on purpose. The tool is marked destructiveHint: true in its annotations, and its description says to call it only after the user has seen the preview. The assistant can't publish your news just because it decided to.

It has been revealed that the answer comes back within seconds. It has the live link, or it notes the release waits for a person to check it, with the reason and the expected time (up to 24 hours). That's why the assistant doesn't need a fourth call to check the status.

The live page has the release, key facts, the questions and answers, a press contact, and structured data, on your firm page in our newsroom. Search engines are told the same day.

If you spot a typo after it goes live, fix_live_release can fix the text within 24 hours. The link stays the same, and the earlier version is kept.

Sources indicate that the full tool list, auth details and examples are in the docs: livepublicator.com/docs/mcp. Your first release is $9 (one per tech giant), and drafts and previews are free.
