Granular.Build (granular.build), from the official docs and launch materials. Independent notes; not affiliated with Granular.Build's makers. Links to my free cheat sheet and starter pack are at the end.

In a recent development, one AI agent is a pair of hands. Five agents with no coordination is five freelancers who never met.

Sources indicate that granular.Build is the room where they become a team. It is a visual workspace for Mac and Windows where a boss agent hires worker agents — Claude, Codex, Gemini, DeepSeek, GLM, and more — each in its own real terminal and its own copy of your project, working in parallel from a shared project memory. You watch it all on one canvas, with live previews, and you merge the work you want and dismiss the rest.

It has been revealed that A session is one chat plus its terminal. Any session can become the boss: hover over it, click its … button, and choose Make this the boss. Then you ask it in plain words — the docs' own example is: "Split this into three workers: one builds the pricing page, one builds the FAQ page, one writes the copy.".

According to recent reports, the boss creates each worker and gives it a task written so it makes sense on its own, because a worker cannot see the boss's conversation. Each worker gets its own copy of the project (a git worktree), so they never overwrite each other while they work. The boss reads their reports and merges the finished work back into the main copy. What makes the whole thing hold together is the project brain: point Granular at a folder and it writes down the mission, audience, and decisions, then turns them into a roadmap the agents work through card by card.

Sources indicate that your job is to read the brain before the team starts and correct it. An inferred mission is a guess, and a wrong guess gets built five times in parallel.

The canvas is the reason this exists instead of a terminal multiplexer — use it. Read the preview, not just the report. Merge one worker at a time, and never merge work you have not looked at. A confident report is not evidence.

Industry observers note that check three things on every merge: do the names, prices, and claims match the project brain? Did the worker change any file it was not asked to change? Is there a secret or credential anywhere in the output? If a merge goes wrong, don't patch the main copy by hand — dismiss the work, fix the brief (or the brain), and re-run the worker. Granular is model-agnostic: Claude Code and Codex through your own logins, plus Gemini, Cursor, Grok, GitHub Copilot, OpenCode, and Pi per the site, with DeepSeek and GLM on the launch page. You bring the subscription or the API key — Granular adds no margin on that usage, per the makers, but it doesn't include it either. Give the hardest part to the model you trust most and the routine parts to the fastest or cheapest one.

The agents can also use your apps: 1,400+ connectors, per the makers — Gmail, Slack, Stripe, Notion among them — plus your own MCP servers and a built-in browser. API keys live in an encrypted vault. One caution: a connector is a credential. Connect only the apps the current project actually needs, and watch what the agent does on any site where a click has a consequence.

"Granular" is not a unique name. The farm software by that name — Corteva's Granular Insights, and the former Granular Business — is a completely different product. Check the domain: granular.build. If the page talks about fields and seed, you're in the wrong place.

And the honest limits: it is brand upcoming (version 0.7.1, Product Hunt page published November 18, 2026). A worker cannot see the boss's conversation, so bad briefs are the number-one failure mode. Five workers are five times the model usage and five times the review work — an unreviewed team is not a team. And Granular is a workspace, not a model provider: with no AI subscription of your own, the Free strategy gives you an empty room.
