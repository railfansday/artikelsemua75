I built Bazaar Ledger, a shop bookkeeping app for Android with a Windows companion, and I want to share what offline-first did to the design.

According to recent reports, the rule. Every bill, payment and stock movement is written to the phone first. The network is optional, so there is no loading spinner between a customer and a receipt.

The ledger underneath. Billing screens are friendly, but every sale, payment, purchase and expense posts to double-entry accounts. That is why the 100+ reports agree with each other: they are different views of one ledger. (Related: How to generate text: using different decoding methods ...)

A server that cannot read. If a shop turns on the optional cloud, the books are sealed on the phone before upload, with keys the server never receives. The cost is real: the server cannot search, repair or analyse a shop's data, so every feature that needs reading has to be opt-in and done on the device. (Related: Hyperparameter Search with Transformers and Ray Tune...)

Industry observers note that posted bills are never edited in place. A correction is a cancelled bill plus a fresh corrected one, both kept, behind a PIN. It is more work to build and far easier to audit.

The AI assistant is optional and narrow. Simple commands are parsed on the phone. When the phone is unsure, the assistant (Anthropic's Claude, through our server) gets only what that one request needs, never the whole book. You review and save by default.

Sources indicate that the app is free for one whole shop. I would like feedback from other Flutter developers on two things: testing sync conflicts when two counters sell the last unit offline, and how you handle thousands of ledger rows on low-end phones.

Play: https://play.google.com/store/apps/details?id=pk.bazaarledger.
