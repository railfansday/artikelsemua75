NGINX2Root: Remote Code Execution vulnerabilities in nginx

🌐 Source: Lwn • 📅 18 Nov 2026 • ⏱️ 29 min read (5803 words, 📚 Deep Dive)
💡 Key Takeaways
  • Xint is reporting that it has discovered a collection of five critical vulnerabilities in the NGINX web server.
  • According to recent reports, xint recommends updating to NGINX 1.31.9, which was just released, and to block the SCTP module on hosts that do not need it until a kernel fix is available.
  • More seriously, it looks like the 'most severe' of the attacks requires sending 128 gigabytes of data; so with luck, we won't see this one be seriously exploited over the internet.
📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Xint is reporting that it has discovered a collection of five critical vulnerabilities in the NGINX web server. The worst flaw, it says, would allow an unauthenticated attacker to execute commands on an affected nginx server with HTTP/2 enabled. The tech giant also reports a local-privilege escalation (LPE) kernel vulnerability, which was introduced in the 4.15 kernel, in the Stream Control Transmission Protocol (SCTP) subsystem. If chained with the NGINX vulnerability, it would allow an attacker to gain root privileges on the host. A kernel patch for this is not yet available.

According to recent reports, xint recommends updating to NGINX 1.31.9, which was just released, and to block the SCTP module on hosts that do not need it until a kernel fix is available. See the mitigations section of their report for more information.

Security researcher reports are heavily skewed. One finds a problem in X, everyone else tests X in other software. That does not mean X is the only thing with holes and that does not mean would-be attackers also focus on X, that means security researchers have herd mode on. It is quite unsurprising to find problems in HTTP/2 and HTTP/3 implementations. They are quite new and complex. They are also trendy, so security researchers will focus on them (hype mode on). HTTP/2 and HTTP/3 also replace and streamline a babel tower of JS and proxy hacks people deployed to try to make HTTP/1 suck less. You bet no researcher is going to focus on those because they are one-of-a-kind site-specific setups. Someone who wants to hole a specific site, OTOH, will have no such scruples.
