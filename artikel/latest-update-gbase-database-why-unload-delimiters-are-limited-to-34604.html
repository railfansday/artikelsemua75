This is a classic delimiter collision, and it is worth understanding how to avoid it in GBase Database.

In GBase Database(GBase 8s), the unload statement allows you to specify a delimiter for exported data.

The delimiter here is |#, a combination of two characters.

Sources indicate that GBase Database supports delimiters of up to four characters. You can combine multiple characters into one delimiter, but a delimiter longer than four characters is rejected rather than silently truncated.

A single character such as | or # may already appear in business data. A combination of two characters is generally less likely to occur naturally in a text field.

The objective is to reduce delimiter collisions, especially when exporting large datasets containing free-form text.

Choosing a delimiter during export is only half the job.

The same delimiter must be specified when importing the file with load.

The export and import operations must use the same delimiter.
