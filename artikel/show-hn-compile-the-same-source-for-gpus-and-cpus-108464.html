📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Industry observers note that xc is a heterogeneous data-parallel language. Write an ordinary loop, in xc or in C, and xcc runs it across every CPU core, on the GPU through Metal, CUDA, Vulkan or WebGPU, across several GPUs from different vendors at once, or on a GPU on another machine, and keeps whichever is fastest. The kernels are generated by xcc itself and carried in the executable, so a build needs no GPU toolkit. Documentation, benchmarks and downloads are at https://compile-xc.org.

This repository holds the compiler, its GUI framework and the tools and applications built with them.

It is one repository, but it is worked on as several separate streams, and each stream stays inside its own tree.

According to recent reports, private/ is not part of the repository. It is ignored by git and holds the working rules, the notes on open and fixed bugs, and other material that is never published. Nothing under it is ever committed.

Build and install the compiler first (see compiler/USAGE.md), then build whichever other tree you are working in against it. (Related: Build A Racetrack codes (November 2026)...)

Recent findings suggest that settings that depend on your machines, such as the Linux test host or the location of the GEM desktop sources, live in build.env at the repository root. Copy build.env.template to build.env and fill in the values you need. build.env is ignored by git. A variable left empty turns off the step that needs it. Sources indicate that pull requests are welcome. CONTRIBUTING.md claims how a change gets into main: the contributor licence agreement you sign once, where changes go, and how to build and test with an installed release. Everyone taking part agrees to the code of conduct. Security problems are reported privately, as SECURITY.md describes.

Recent findings suggest that every benchmark figure on the site is measured on hardware the project has bought, and the machines that matter most for data-parallel work are expensive. A loan or donation goes straight into the compiler: a back end and a runtime tuned on the device, kept working by being tested on it every release, and its figures published beside the others.
