GL.iNet Router and KVM Security Incident.

Issued November 20, 2026  |  Last updated November 21, 2026 (UTC).

In a recent development, on November 20, 2026, GL.iNet identified a vulnerability in its cloud remote management services. An unauthorized party exploited the vulnerability to access and install malicious software on some GL.iNet routers and KVM devices. (Related: My Journey to a serverless transformers pipeline on Goo...)

The attack path has been blocked. We fixed the cloud vulnerability and blocked the access used in this incident. Devices can no longer be newly infected through this attack path. These measures do not remove malware from devices that were already infected. (Related: Large Language Models: A Newly introduced Moore's Law?...)

Security firmware: Stable firmware with security fixes for both routers and KVM devices is scheduled for November 22, 2026. We recommend installing the stable patch for your model as soon as it becomes available, even if the check finds no signs of infection.

Follow the steps below to check your device. For both routers and KVM devices, look for the exact text crond -i /tmp/.log within the details of a running process. The process entry may contain other information.

Sources indicate that in the KVM web interface, go to Toolbox → Terminal → Access. Run the command for your model in the KVM’s terminal, not on the connected computer.

Recent findings suggest that as a precaution, check for unfamiliar programs, browser extensions or user accounts; unexpected startup items or scheduled tasks; and unusual settings changes or network activity. Run a full scan with up-to-date security software.

KVM security fixes are already available through the beta channel for the models listed below. If your KVM shows signs of infection, you can install the beta update for your model now.

For questions, please contact support@gl-inet.com.

To report a security concern, contact security@gl-inet.com.

We apologize for the concern this may cause and are committed to keeping you informed.
