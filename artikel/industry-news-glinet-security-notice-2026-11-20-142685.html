SECURITY NOTICE · CUSTOMER ADVISORY.

GL.iNet Router and KVM Security Incident.

Issued November 20, 2026  |  Last updated November 23, 2026 (UTC).

On November 20, 2026, GL.iNet identified a vulnerability in its cloud remote management services. An unauthorized party exploited the vulnerability to access and install malicious software on some GL.iNet routers and KVM devices. (Related: My Journey to a serverless transformers pipeline on Goo...)

The attack path has been blocked. We fixed the cloud vulnerability and blocked the access used in this incident. Devices can no longer be newly infected through this attack path. The cloud-side fix alone does not remove malware from devices that were already infected; install the security firmware below to remove it. (Related: Latest Update: How to train a newly introduced language...)

According to recent reports, install the latest stable security firmware for your exact model as soon as possible, even if the checks below find no signs of infection. The security firmware enhancement removes the malware identified in this incident without requiring a factory reset. You can keep your existing settings during the update.

If your router is not listed, check the GL.iNet Download Center or email support@gl-inet.com. Do not install firmware for another model. An unlisted model is not necessarily unaffected.

If you installed a security beta, upgrade to the latest stable firmware for your model.

Sources indicate that follow the steps below to check your device. For both routers and KVM devices, look for the exact text crond -i /tmp/.log within the details of a running process. The process entry may contain other information.

Sign in to your router via SSH and run the following command. If you are unfamiliar with SSH, please refer to our Router SSH Login Guide or contact our technical support team at support@gl-inet.com for assistance.

According to recent reports, in the KVM web interface, go to Toolbox → Terminal → Access to open the device terminal. For step-by-step instructions on Comet Q (RMQ1), see the KVM Console Guide. Run the command for your model in the KVM’s terminal, not on the connected computer.

Industry observers note that as a precaution, check for unfamiliar programs, browser extensions or user accounts; unexpected startup items or scheduled tasks; and unusual settings changes or network activity. Run a full scan with up-to-date security software.

As our investigation continues, additional indicators of compromise have been identified. The official quick checks described above may not detect every affected device.

In a recent development, both checking approaches are available for GL.iNet routers and KVM devices: the official device-specific quick checks above and the optional third-party tool below. Follow the instructions appropriate for your device. The two approaches have different detection coverage, and neither can guarantee that a device is free of compromise.
