In a recent development, brizy has released version 1.9.5 of its AI website builder, replacing the use of Unsplash stock photos in the AI generation workflow with generated imagery. The upgrade also changes how the builder assembles pages. Brizy claims it can now generate an individual section from a prompt instead of relying on ready-made blocks for the page design.

The changes give users a way to revise part of a site without discarding a draft that already works. They also make a distinction that matters for businesses: a stock image is an existing photograph chosen for a page, whereas a generated image can be tailored to the prompt without depicting a real product, location or member of staff. That makes some designs easier to prototype, but creates more for the site owner to verify before going live. (Related: Training Design for Text-to-Image Models: Lessons from ...)

In a recent development, in its version 1.9.5 announcement, Brizy says it uses components to construct a layout and can take design or content references as input. Those references can include images or HTML for layout direction and documents for source material. An owner could start with a brand reference and then regenerate a services section when the first version misses the point, rather than regenerate every page just to change one area. Industry observers note that the organization also indicates the release improves support for Chinese, Japanese, Korean, Russian and Arabic, including right-to-left layouts for Arabic. On multilingual sites, that affects more than text. Menus, buttons and page sections must remain usable when a language runs in the other direction or when the translation takes up more space than the original. An initial generation still needs review in each language, especially on mobile.

Brizy’s separate Cloud changelog shows that the editor and the generation flow have their own updates. For example, Cloud has added AI-assisted creation of upcoming pages in an existing project. That is different from the new release’s ability to regenerate a single section during website creation. It is worth checking which editing surface a feature belongs to before adopting it as part of a workflow.

It has been revealed that brizy’s support guidance for WordPress import describes a generation and refinement stage before the user imports a design. It advises completing AI-based customization before the import, because the same generation controls are not available afterward in that workflow. For teams preparing a WordPress launch, that makes the handoff a good point to check copy, images and layout rather than expecting every generation option to remain available after import.

Industry observers note that generated imagery is useful for abstract backgrounds or illustrations when no suitable photograph exists. It is a less suitable substitute when customers need to see the actual item they are buying. Uploaded documents present a similar concern for copy: the text may look polished even if it misstates a price, service area or refund condition. Giving the builder reliable source material helps, but a person still needs to compare the published wording against it.

In a recent development, there is also a cost to repeated experimentation. Brizy’s Cloud terms say designated AI features use credits and that consumption varies with the action. A team evaluating the update can try one representative page, revise just the section that needs work, and check how much editing remains before publication. The useful measure is not how quickly the first design appears, but whether the site is faster to finish without losing control of what visitors see.
