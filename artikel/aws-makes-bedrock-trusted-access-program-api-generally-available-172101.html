Recent findings suggest that amazon Web Services announced on November 24, 2026 that its Amazon Bedrock trusted access program API is generally available, giving customers one interface to discover, request and enroll in model-provider programs. Its first two offerings are Anthropic’s Enterprise Frontier Safeguards (EFS) and Enterprise Data Controls (EDC), both in public preview.

It has been revealed that the API standardizes programs that can change which models a customer can use or how Bedrock retains and reviews requests. Administrators can work at individual-account, AWS Organizations or named-project scope, using existing AWS Identity and Access Management (IAM) policies and service control policies to decide who may opt in. Additional provider offerings appear in the same catalog and follow the same steps as they are added. (Related: Breaking: Future Value Calculator: How to Project Your ...)

Recent findings suggest that approval and participation remain separate decisions. The provider, or AWS with the provider’s authorization, determines eligibility; the customer then accepts the program’s terms and enrolls at the approved scope. The trusted access program documentation also establishes a hierarchy: project enrollment overrides account enrollment, which overrides organization enrollment. Customers can opt out while retaining approval, and AWS CloudTrail records the enrollment calls and the identity behind them. (Related: How to Start a Side Business While Working Full-Time...)

The preview covers Claude Fable and Claude Mythos models, together with Claude Opus 5.5 and Claude Sonnet 5.5 when used through the Cyber Verification Program. AWS says EFS was designed with more than 100 customers, including a quarter of the Fortune 100 and organizations in healthcare, financial services and law.

It has been revealed that under EFS, prompts and responses are encrypted with the customer’s AWS Key Management Service (KMS) key and written to its Amazon Simple Storage Service (S3) bucket. AWS states that human reviewers at AWS and Anthropic do not access the retained content and that it is not used for training. EDC instead places retained content in Amazon-managed storage with AWS-managed keys for up to 30 days, removing the need to configure a bucket or key. Anthropic does not retain prompts or completions under either offering, and with EFS Amazon Bedrock keeps no copy in its own storage.

Both offerings apply automated monitoring across requests to risks such as offensive cyber operations or agents exceeding a user’s instructions. The programs’ review model assigns flagged activity to the customer’s own team. The choice between them therefore turns on data-handling policy: EFS keeps retained content in customer-controlled storage, while EDC simplifies setup by using Amazon-managed retention.

It has been revealed that for EFS, a case lists flagged requests and points to their transcripts in the customer’s bucket. The customer must answer within seven calendar days with violation or no_violation; the first valid response is final. A status of window_ended records an expired review window without a valid response and does not establish clearance. Repeated failures to respond can lead to account suspension. AWS’s comparison of the storage routes identifies another material distinction: EDC cases are not delivered during the public preview.

Industry observers note that EFS configuration is regional. Each Region where covered models are called needs a KMS key and S3 bucket in that same Region. Records normally arrive within minutes, although retries can continue for up to 72 hours. If Bedrock loses required key or bucket access for 24 hours, covered-model serving stops for the affected scope and Region.

Industry observers note that the public preview is limited to customers already enrolled in EFS zero data retention, and access requests go through an AWS account team. Joining disables zero retention for the accounts or projects entered into the preview, while other accounts retain it. The EFS and EDC documentation recommends test accounts and test traffic, warns against sending regulated data such as PII or PHI, and notes that APIs, IAM action names and endpoints may change before general availability.

Sources indicate that AWS and Anthropic do not charge for EFS or EDC or change model pricing, behavior or rate limits. EFS customers still pay standard S3 and KMS charges; S3 data-transfer charges can also apply when a bucket is outside the Region where automated review runs. That review runs in US East (N. Virginia) and Europe (Ireland), with the preview covering covered-model requests through US and EU geographic cross-Region inference profiles and the global cross-Region inference profile.

Eligible customers can continue using current Claude Fable models and existing Cyber Verification Program models internally with zero data retention through at least June 30, 2027; AWS describes EFS as the longer-term route afterward. For organizations using that interim arrangement, EFS makes customer-controlled storage and customer-led review part of the operating conditions for continued access to Anthropic’s covered models.
