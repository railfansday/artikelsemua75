In a recent development, minipg is PostgreSQL as one executable, ready to use, with no server to configure. A .pgdb directory is the database: its data, config, credentials, and Postgres version all live inside it, and minipg app.pgdb opens a psql shell on it. A server starts when a command needs one and stops on its own when it's idle. (Related: Tech Report: AI for Game Development: Creating a Farmin...)

minipg embeds Docker Hub's postgres:18-alpine image and runs it with h9, used as a Zig library. h9's Linux personality runs Alpine's own Postgres binaries directly on the host's hypervisor, with h9's Plan 9 kernel answering their system calls. There's no Linux kernel to boot, no VM image, and no Docker.

Industry observers note that the demo downloads about 35 MB. It needs JavaScript Promise Integration, which Chrome and Edge have from version 137; other browsers are getting it. It can also be opened on its own page. (Related: Industry News: huggingface_hub v1.0: Five Years of Buil...)

According to recent reports, the demo runs minipg's Linux build, which runs inside the Postgres image itself. It starts Postgres as ordinary processes and serves on a unix socket, since a page has no TCP. Fresh databases come from a template cluster made at build time, because initdb takes half a minute on v86.

It has been revealed that A .pgdb holds minipg.toml (settings and the generated superuser password) and pgdata/, Postgres's data directory as plain files. A stopped one can be copied like any directory. Newly introduced clusters use Postgres's builtin C.UTF-8 locale, which sorts the same on every platform.

The README lists every command, and the manual is the full guide.

Exactly one process runs Postgres for a .pgdb, enforced by a lock. It holds the server's h9 machine, whose Linux root is the unpacked image and whose writable working directory is the .pgdb. The image's docker-entrypoint.sh initializes the cluster on first start. Commands never host Postgres themselves. If no server is running, they start one in the background and use it. psql, pg_dump, and the other tools each run in their own short-lived h9 machine (about 90 ms to start) over the same root.

Industry observers note that the source is on GitHub, under the MIT license. Building needs Zig 0.16, plus curl, jq, tar, and xz for the root:.

Sources indicate that minipg is early, and h9's Linux personality is young. On h9's native backend, Postgres is about 2x slower than native for one client, and slower under load. Don't trust it with data you can't recreate yet.
