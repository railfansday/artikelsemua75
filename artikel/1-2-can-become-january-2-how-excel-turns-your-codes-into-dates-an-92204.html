In a recent development, open a CSV the usual way — double-click — and Excel can automatically convert some values as it opens the file. Depending on your regional settings, Excel can interpret product codes as dates. In this example:.

(The codes are dummy data; the product names — bolt set, adapter, cable — are made up.).

Nothing in the file was broken. The damage happens at import: Excel sees a run of digits and symbols and decides it must be a date. And once a cell has been converted, changing its format to Text does not recover the original code. Reimport the original CSV with the code column set to Text — the only intact copy is the CSV file itself, so don't save over it.

This post focuses on stopping that conversion when you import a CSV into Excel.

According to recent reports, A CSV field carries no type information. The file is plain text, and it doesn't say whether 1-2 is a date or a label.

Recent findings suggest that when Excel opens a CSV directly, it guesses the type of each cell. A pattern like digits, a hyphen, and more digits looks like a date, so Excel converts it — and a code that was never a date is now one. This is the same automatic type detection discussed in the earlier post about leading zeros and scientific notation: Excel decides the type for you when it opens the file.

The real problem is a category error: product codes like 1-2, 3-4, and 11-12 are identifiers, not dates. They only look like dates; they behave like text. The import step doesn't know that — unless you tell it.
