Latest Update: Bitcoin Core fixes a bug that can stall nodes, leaving 29.x users to upgrade

🌐 Source: Cryptoslate • 📅 23 Nov 2026 • ⏱️ 2 min read (476 words, 📖 Standard)

  • According to recent reports, bitcoin Core rated the flaw medium severity in its security advisory, which identifies it as CVE-2026-117348.
  • For operators running versions 30.0 through 30.4, the maintenance revision is 30.5.
📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Bitcoin Core released versions 30.5 and 31.3 on Nov. 20 with a fix for a flaw that can temporarily stop a Bitcoin node from processing blocks and transactions. Operators on affected 30.x and 31.x releases can patch within their current release lines. Operators on affected 29.x releases need to move to a newer line.

According to recent reports, bitcoin Core rated the flaw medium severity in its security advisory, which identifies it as CVE-2026-117348. The project indicates a peer can trigger a temporary interruption in block and transaction processing on an affected node.

For operators running versions 30.0 through 30.4, the maintenance revision is 30.5. Operators running 31.0 through 31.2 can update to 31.3.

Recent findings suggest that bitcoin Core 32.1 shipped with the fix on Oct. 27. The project calls the flaw easy to discover and notes in its 32.1 release notes that it would disclose easily discoverable vulnerabilities fixed in that release once patches were available for all maintained major versions. The two maintenance updates and the public advisory came out on the same day.

Sources indicate that the affected 29.x versions run from 29.0 through 29.5. The project’s software lifecycle schedule dates the end of 29.x support to Oct. 27, the day 32.1 shipped. Bitcoin Core notes 29.x will receive no fix for this flaw. An operator on that line can move to one of the three releases the advisory identifies as fixed, including either of the November maintenance releases.

According to recent reports, bitcoin Core maintains its three newest major release lines. When a newly introduced major line enters that window, the oldest drops out. The project recommends running the latest maintenance release of the newest major version an operator can move to.

Sources indicate that the 32.1 release notes say operators can upgrade directly from an end-of-life version. They instruct operators to let the older version shut down completely before installing the update. The move can take extra time if the node’s data directory needs to be migrated, a practical consideration for operators still running 29.x.
