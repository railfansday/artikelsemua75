OpenAI Getting Rid of Custom GPTs and Moving to Plugin Architecture

OpenAI has confirmed it will retire Custom GPTs and move the specialized workflows built around them to a latest plugin architecture spanning ChatGPT and its Codex coding agent.

Custom GPT retirement is currently scheduled for Dec. 11, 2026, although the organization says timing and migration availability can vary by account and workspace.

Sources indicate that for affected Enterprise workspaces, OpenAI's current migration schedule targets Oct. 26 for ending creation of fresh Custom GPTs. Qualifying Enterprise customers with approved deferrals can continue using them until Feb. 11, 2027.

Rather than maintaining separate customized versions of ChatGPT, OpenAI is shifting customization toward plugins that can package reusable instructions, reference material, and connections to outside services. (Related: Latest Update: Alyah ⭐️: Toward Robust Evaluation of Em...)

Under OpenAI's plugin architecture, a plugin can include one or more skills containing instructions and resources for repeatable workflows, a Model Context Protocol (MCP) server exposing tools and external systems, or both. ChatGPT and Codex share a universal plugin directory, although some capabilities can remain specific to a particular environment.

Industry observers note that for organizations, that makes the change more than a simple renaming exercise. A company could package recurring workflows into skills while using MCP servers or connected apps to give those workflows access to enterprise systems and data.

OpenAI indicates creators will be able to migrate an existing GPT through the My GPTs interface. The GPT's instructions become a skill in the replacement plugin, while knowledge files are copied into plugin reference files and connected apps can be carried over.

Not everything transfers automatically. Existing GPT conversations do not migrate, the selected model does not carry over, and Custom Actions may have to be rebuilt using an available app or a custom MCP server.

Sharing also changes. Migrated plugins start private, existing GPT people do not automatically receive access to the replacement, and prior sharing settings do not carry over.

According to recent reports, openAI is also cautioning organizations against assuming that migration will preserve behavior exactly. "A migrated plugin may respond differently," the company says, recommending that consumers retest familiar prompts, reference-material use, required output formats, and integrations before relying on the replacement.

That warning has contributed to pushback from some GPT builders, who argue that plugins do not fully reproduce the dedicated and predictable environment of a Custom GPT. Other complaints have focused on sharing, migration complexity, and differences in how migrated workflows use instructions and reference material.

Recent findings suggest that despite those concerns, OpenAI is clearly consolidating around plugins as its common mechanism for extending its AI products. Its developer documentation now describes plugins as packages users can "discover, install, share, and publish" across ChatGPT and Codex, replacing the separate-custom-assistant model with reusable AI capabilities that can be combined with enterprise tools and services.

For more information, go to the OpenAI site.
