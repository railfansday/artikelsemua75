YAML is a massive and complicated spec, so it didn't even occur to me that this was invalid. Instead, I opened tree-sitter-yaml#36 to "fix" it. I've now opened tree-sitter-yaml#51 to revert that misbegotten fix.

On GitHub's side, I'm not sure if they have a clean path towards spec conformance here. Much of the code behind Actions is proprietary, but it seems likely that the underlying parser on their end is YamlDotNet.

In a recent development, actions appears to use YamlDotNet 5.3.0, which was released in 2018. However, even upgrading to the newest version (18.1.0 as of writing) wouldn't fix this particular bug, since it's still present on that version (note the !isSingleQuoted guard).

My best guess is that a 2020 patch (YamlDotNet#467) only fixed the double-quoted form because YAML's official test suite only tests rule 8.2.3 with a double-quoted string, despite it applying to both forms.
