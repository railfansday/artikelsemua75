Sources indicate that leonida is a static recompilation project. The Xbox Series CPU is x86-64 like a PC, so the game's code is loaded and run natively, and the console's system software is reimplemented. The console's precompiled RDNA2 GPU programs are translated to SPIR-V for Vulkan. The game's models, textures and audio are read from your package. All of this happens on your PC, from your own copy of the game. (Related: Latest Update: University debuts $5m smart system that ...)

Recent findings suggest that this repository does not contain the game, keys or an executable, and it does not explain how to get them. You need your own copy, with its files already readable on disk. Nothing here decrypts or works around any protection. Everything the build creates (the generated shaders, extracted assets, the runtime folder and your saves) comes from your game and stays on your PC. Never share those files. Industry observers note that the port isn't downloaded ready-made. It's built on your PC from your own copy.

It finds your copy of the game by itself: it looks in Downloads, Desktop, Documents, Games, your home folder and the top of every drive, two folders deep. It recognises the version from a few file sizes, without reading anything large. If you have more than one copy it asks which one, and if it finds none it asks you to paste the folder. Before starting it checks that everything below is installed and that there is enough free space, and it lists anything missing in one go. The result goes to Documents\Leonida. A stopped build continues where it left off.

Your game folder is the one that holds MicrosoftGame.Config and the .rpf archives, as plain files.

According to recent reports, --wave64-emulate decides whether wave64 compute and mesh shaders are translated to be exact on any subgroup size (see "Wave64 emulation" in docs/design.md). NVIDIA and Intel GPUs have 32-wide subgroups and need it. The default, auto, asks vulkaninfo (part of the Vulkan SDK) and turns it on unless every GPU reports 64-wide subgroups, or when it can't tell; it also turns it on when the GPU the runtime would use can't be made to run compute and mesh shaders 64-wide. The mode is saved next to the translated shaders, and changing it translates them again. With auto, a work folder that previously used emulation keeps it for later translations and retries, even if the current GPU supports native wave64. Use --wave64-emulate off to translate it natively.

It has been revealed that the build records which translator sources produced the shaders. A change to those files reruns translation using the saved disassembly. Older work folders need one translation after upgrading to record this information.

Stages run in order: check, shaders, assets, runtime, pipelines (creates every translated shader on your GPU driver and saves a pipeline cache, so the first boot doesn't compile them). The shader translation is the longest step: it runs on --jobs processes (half the CPU threads by default).

--wav is off by default because 16-bit PCM WAV is several times larger than Ogg Opus. It decodes the repackaged Ogg Opus streams to work\assets\audio\wav after the audio bank step; existing WAV files are skipped when a build resumes.

Industry observers note that make_game.py runs on Linux too. The pipelines stage uses the vk_pipeline_check built above (runtime/build/linux, or runtime/build). The runtime stage builds on Windows only, so on Linux it needs a Windows build of runtime/; without one it is left out of the default stages, and asking for it fails before any work starts.

Recent findings suggest that the loader is a Windows program and runs under Wine or Proton; CI runs its tests under Wine on every change to runtime/ (the wine job of the Runtime workflow). Give the runtime stage a folder with gta6rt.exe and gta6rt_tls_host.dll, such as the runtime-windows artifact of that workflow's windows job, unzipped:.

In a recent development, it copies both files into --out and writes gta6rt.sh next to them, which starts gta6rt.exe with wine, or with the Wine named by WINE (for Proton, its files/bin/wine). The same option skips the build on Windows.

The translator's runtime contract (user SGPRs, push constants, memory model, bindless images, vertex fetch, system values) and all the format notes are in docs/design.md; the format, asset, runtime and validation notes are indexed in docs/README.md. The Xbox D3D12 plan is in docs/d3d12_vulkan.md. Audio bank formats and the export tools are in docs/audio.md; docs/related_projects.md records the prior art we may read and the licence limits on it.
