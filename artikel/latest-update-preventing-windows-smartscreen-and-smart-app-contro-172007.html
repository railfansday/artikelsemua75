In a recent development, when a frozen Python backend dies immediately after launch on a Windows machine running Smart App Control (SAC), the failure rarely happens inside your Python code. It happens at the Windows loader boundary when a native module fails policy verification. A PyInstaller build is not a single monolithic binary; it is a bootloader executable plus dozens or hundreds of Portable Executable (PE) images—python3xx.dll, the VC++ runtime, C-extension .pyd files (which are structurally standard Windows DLLs), and third-party native libraries from wheels like NumPy, SQLite, OpenSSL, or PySide. When the bootloader calls LoadLibraryExW to map a bundled .pyd or .dll into the process address space, Windows evaluates that child image against its security policy. If Smart App Control blocks that specific module with "An Application Control policy has blocked this file", the loader aborts mapping the image and returns a module-load failure up through Python's import machinery, raising an unhandled ImportError or access/loader fault that kills the process before your main application window or recovery handler ever runs.

Sources indicate that signing only the top-level .exe fails to prevent this crash because Windows does not inherit code-signing trust transitively from a signed parent process to every unsigned module it loads. In a standard Windows PE load path, the kernel and user-mode loader inspect the PE header and Authenticode signature of each mapped image independently. Even when app.exe carries a valid cryptographic signature, an unsigned _ssl.pyd or libcrypto-3.dll remains an unverified PE image on disk. Under Smart App Control—which enforces strict policy rules on non-reputable or unsigned code rather than merely warning the user like classic SmartScreen—an unsigned third-party DLL or PYD has no trusted signer chain to vouch for it. The causal chain is direct: unsigned wheel binary stays unsigned during freeze -> Windows loader maps the .pyd/.dll as a separate PE image -> SAC policy rejects the unverified image -> import/loader error terminates the Python runtime at startup.
