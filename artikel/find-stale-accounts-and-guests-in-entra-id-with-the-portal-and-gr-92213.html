Industry observers note that accounts outlive the people they were made for. A leaver whose account was never closed, a contractor's guest invite from two years ago: each is an extra way in that nobody is watching. Microsoft states there is no built-in report for inactive user accounts, so you build one from the last sign-in date. (Related: Industry News: These are the Senate Democrats backing S...)

This is a half-hour, read-only way to do it. You need a licence note, one portal view, four GET queries in Graph Explorer, and a few traps to avoid.

Two cautions from Microsoft: the value can take up to 24 hours to upgrade, and it can be blank if the account never attempted a sign-in or its last attempt was before April 2020. Blank means look closer, not delete. (Related: IShowSpeed breaks down in tears after finishing GTA 6 i...)

Graph Explorer is Microsoft's browser tool for trying Graph requests. Microsoft warns that if you sign in with an organisational account, a write request can change the tenant. So leave the method on GET, and when a query asks for permission, use Modify permissions to consent to AuditLog.Read.All and User.Read.All only.

Microsoft documents userType as Member or Guest, filterable with eq. Its pages do not say whether selecting signInActivity alongside that filter is allowed, so if Graph rejects it, drop signInActivity from $select and look guests up individually.

This finds invitations nobody accepted. Microsoft claims externalUserState is set for guests invited through the invitation API, so guests created another way may not appear.

For a report without queries, go to ID Governance > Dashboard, find the Guest access governance card and select View inactive guests. Microsoft notes it uses 90 days by default, counts from the creation date for guests who never signed in, refreshes daily and can be downloaded. It needs Entra ID Governance or the Entra Suite, so on P1 alone the Graph queries are your route.

It has been revealed that microsoft's questions for each inactive user: is the person still employed, do they still need access, is the account needed for another reason? Add two practical ones. Is it a shared, service or emergency access account that rarely signs in by design? Could failed attempts, perhaps an attacker's, be refreshing the date on an account nobody uses?

Sources indicate that when you do act, Microsoft's access review pattern for stale guests is to block sign-in for 30 days and then remove the user, and it says a deleted guest can be restored for up to 30 days. Access reviews of inactive guests need Entra ID Governance or the Entra Suite. A named person makes any change; nothing above changes a tenant.
