Bitcoin Core Patches Node-Stall Bug Found by Block’s AI Scanner

Bitcoin Core developers have disclosed and patched a medium-severity bug that let an attacker temporarily freeze a node’s processing of blocks and transactions, a flaw first flagged by an AI scanner built by Block’s Spiral.

The vulnerability, tracked as CVE-2026-117348, is fixed in Bitcoin Core versions 30.5, 31.3 and 32.1. The 30.5 and 31.3 releases shipped Friday alongside the public advisory, while 32.1 has carried the fix since Oct. 27.

Affected versions run from 29.0 through 29.5, 30.0 through 30.4 and 31.0 through 31.2. The 29.x series has reached end of life and will not get a fix, so operators on that branch need to move to a newer release.

Bitcoin Core keeps “orphan” transactions, whose parent transactions it has not yet seen, and asks peers that announce them for the missing pieces. Since version 29.0, the software builds a list of an orphan’s parents and checks each one against its mempool and filters before deciding what to request.

A single inv message can carry up to 50,000 entries, and the software did not skip duplicates. An attacker could send a node an orphan with thousands of missing parents, then send messages repeating that transaction’s ID 50,000 times.

It has been revealed that “Each such message stalls the node for over a dozen seconds, during which it processes no messages from other peers, including blocks,” the advisory noted. Sending more messages could stretch the disruption out.

The fix makes the node process each transaction declared in an inv message only once. The advisory describes a temporary denial-of-service problem and does not describe any way to steal bitcoin or permanently damage a node. It also does not say whether the bug was ever exploited.

According to recent reports, for a business running an affected node, the stalls could still matter. An exchange could be slow to credit deposits, and a miner could keep working on an outdated view of the chain while its node is stuck.

The advisory credits an automated LLM scan run through Elias Rohrer’s Project Loupe at Spiral, Block’s open-source bitcoin development arm. Bitcoin Core developer Gregory Sanders validated the finding and brought it to the project’s security team. (Related: Industry News: Block Sparse Matrices for Smaller and Fa...)

Loupe is a free scanner that runs AI agents over open-source bitcoin code and only reports findings backed by a working test case. Bitcoin Core, BDK, LDK, rust-bitcoin, Cashu, Blockstream Jade, bitcoinj and SRI signed up for its first round of scans. Rohrer mentioned on a recent podcast that Spiral started the project around March and began continuous scanning in May, with Bitcoin Core in the first batch.

It has been revealed that loupe reported the glitch on July 8. A developer known as Stutxo independently reported it on Aug. 4, the same day Sanders opened a pull request with the fix, which was merged two days later. The fix was backported to the 30.x and 31.x branches on Nov. 17.

Bitcoin Core rated the bug “easily discoverable.” Under a policy the project adopted in October, flaws in that category get fixes backported to every maintained version and a public advisory as soon as patched releases ship, rather than a months-long embargo. Security work across bitcoin software has been busy this fall, from a Linux kernel flaw that prompted a Lightning fix to a upcoming security analysis of a post-quantum signature proposal. Rohrer has said Loupe produces a high volume of reports, which some projects found noisy, and that the team is working to cut false positives.

In a recent development, this is not Loupe’s first Bitcoin Core finding. Developers on an Optech podcast on Nov. 3 discussed three earlier Core security advisories that the scanner had found. Other researchers reported some of the same issues, but only after Loupe did.
