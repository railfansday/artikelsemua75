There's a new genre of HN/dev.to posts: "Give Your AI Agent a Wallet It Can't Overspend." Spend caps are table stakes now — but a cap only tells you the agent stopped. It doesn't tell you why it was looping.

An agent stuck in a retry loop doesn't just waste tokens — it burns them quadratically. Each retry re-sends the growing context. Our loop detector caught a real run where iteration 40 cost 40x iteration 1, all inside a nominally "cheap" model tier. (Related: How to train a new language model from scratch using Tr...)

The fix isn't a bigger cap. It's a loop signature: hash (tool + canonicalized args) per step, flag when the same signature repeats ≥3 times, and fail CI on --fail-on-loops.
