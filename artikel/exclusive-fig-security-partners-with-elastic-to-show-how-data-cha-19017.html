Security operations startup Fig Security Inc. today unveiled an integration partnership with Elastic N.V. that it indicates gives security teams visibility into how data changes affect their detection coverage. (Related: Is Social Security Taxable? How to Calculate What You O...)

Recent findings suggest that the partnership sees Fig’s capabilities for mapping detection dependencies now integrating with Elastic Security, the open security operations platform from Elastic. The platform offers prebuilt integrations and detection rules to establish coverage from day one, with Fig claimed to help security operations engineers safeguard that coverage as their environments evolve. (Related: Gift Tax Rules: How Much Can You Give Tax-Free?...)

It has been revealed that detection rules are dependent on data arriving in the structure they expect, including the fields and values needed to identify suspicious activity. According to Fig, those dependencies can break when changes are made in tools that the security team does not own. The resulting problem, which Fig calls drift, leaves rules active while the data feeding them is missing the information needed to catch an attack.

Once connected through a read-only application programming interface key, Fig’s Security Data Lineage feature maps an Elastic environment’s sources through pipelines, mappings and fields to the detection rules that use them. Any change to a source, pipeline or mapping is noted to have Fig identify the affected detections, along with a suggested repair.

Recent findings suggest that “Elastic gives security teams control over their data, and Fig gives them control over the engineering around it,” noted Gal Shafir, co-founder and chief executive of Fig, who previously led global security architecture for Google Cloud Security. Teams are able to test each change against their own environment, he said, before shipping it as code.

Environments “never stop changing,” according to Jamie Hynds, director of product at Elastic, who stated Fig traces those changes to the detection rules that depend on them so that SecOps teams can maintain their coverage.

In a recent development, fig also works alongside Elastic’s Automatic Import and AI Agent, two features designed to help teams build latest integrations and custom rules as their requirements grow. Changes tested in Fig against the organization’s own data can then be shipped as code using continuous integration and continuous delivery, with version control and one-click rollback included.

The integration is also aimed at organizations moving to Elastic Security from another security information and event management platform. After Elastic’s Automatic Migration has translated their existing detection rules, Fig checks each translated rule against the data available in Elastic ahead of cutover. Rules that need rework are flagged, with a recommended fix for each.

In a recent development, founded in 2025 by Shafir, Nir Loya Dahan and Roy Haimof, Fig released in March with $38 million in seed and Series A funding from Team8 and Ten Eleven Ventures. The firm added an AI agent and software-style deployment tools to its platform in July.

The Fig and Elastic integration is available now, with demonstrations offered through Fig’s website.
