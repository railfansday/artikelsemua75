This is where Composite Primary Key fits in. It is created with shop_id , inventory_item_id and inventory_group_id in the same order + ID field (why? Keep reading).

Industry observers note that let me speed this up a bit. All the rows need to have a natural order for database to store. If you don't provide a Primay key, it creates it's own internal Primary Key as it is needed to store the data in some order.

In a recent development, this Primary Key is used to create Clustered Index. Clustered Index defines the order in which rows are ordered when stored (physically in the B-tree Pages).

A non-clustered Index is just index on a specific column with pointers to Clustered Index. Thus, row insertion, deletion or updation need to patch the clustered index as well as the non-clustered indexes. (See, this is why indexes make write slower databases).
