Tech Report: Floppy3.5: A portable 3.5-inch floppy WiFi NAS

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Industry observers note that floppy3.5 is a 3.5" floppy disk portable WiFi NAS. It reads photos from the floppy disks of old digital cameras like the Sony Mavica. It reveals the photos on a web page through WiFi. It can also copy the photos to a microSD card expanding the amount of photos you can take on the move.

It can read any FAT12 1.44 MB HD disk. It highlights the files in the root folder of the disk on the web page and can copy them to the SD card.

In a recent development, the two processors are on one custom PCB. The RP2354A controller uses the Greaseweazle host protocol. You can also use the gw tool with the controller through the secondary USB. The ESP32-S3 bridge controls the controller through a custom SPI link. The bridge decodes the disk and demonstrates the photos on a web page. Both are OTA updatable.

Controller: You must have pico-sdk 2.x (for the RP2350), arm-none-eabi-gcc, CMake and Ninja.

In a recent development, bridge: You must have ESP-IDF v5.2 or later. The first build downloads the managed components (mdns, qrcode and led_strip).

Use the same procedure for firmware/esp32-bringup/.

Industry observers note that host tests: These tests do not need a board or a target toolchain. Run test/host/build.ps1 in firmware/esp32 or in firmware/rp2354. You can use TinyCC, gcc or clang.

If the password is incorrect the device tries 5 times after it goes back to the setup mode.

Industry observers note that each disk gets a different folder. This is necessary because a camera starts the file numbers again at MVC-00001 after you erase the disk. The device compares the contents of the files (SHA-256). It does not copy a photo that is already on the card. If the card already has a copy of the full disk, the device does not copy the disk. To copy the disk again, do a long push on SAVE.

The LCD looks like a segment display. Unused segments and icons show as light "ghosts" and come on in dark ink when they are active.

The controller is a USB CDC device with the VID:PID 2E8A:000A. The gw tool does not find the device automatically. Thus, you must give the port:.

Sources indicate that the controller speaks the Greaseweazle protocol by Keir Fraser (keirf/greaseweazle), and its firmware is a port of the Greaseweazle firmware to the RP2354. The command handling follows his firmware closely. The flux engine, the part that reads and writes the disk signal, was reworked to use the RP2354's own hardware: PIO programs and DMA take the place of the STM32 timers that Greaseweazle uses.
