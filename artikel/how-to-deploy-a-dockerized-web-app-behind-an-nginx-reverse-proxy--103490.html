Industry observers note that running a containerized web application directly on a public port like :3000 or :8080 works during local development, but it creates serious security and reliability gaps in production. Exposing a container port directly to the internet leaves your traffic unencrypted over plain HTTP, makes managing multiple services on a single server difficult, and bypasses reverse-proxy protections like rate limiting and clean header forwarding. When developers run docker run -p 8080:80 ..., Docker binds port 8080 to 0.0.0.0 (every network interface on the host) and automatically modifies iptables rules—often bypassing UFW completely. That means anyone who knows your server's IP address could visit http://YOUR_SERVER_IP:8080 and bypass Nginx and HTTPS altogether.

To prevent this, explicitly bind the host port to 127.0.0.1 so only processes running on the same server (like Nginx) can reach the container.
