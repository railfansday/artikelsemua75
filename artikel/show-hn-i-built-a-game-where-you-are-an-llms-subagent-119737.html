A browser game where your manager is an AI agent, and it believes you are its subagent.

It has been revealed that the manager (a real LLM: Claude, GPT, Gemini, DeepSeek, GLM, Kimi) is set up like any orchestrator. It has a task queue, read-only access to the machine, and a tool that "spawns a subagent". The subagent is you. Its instructions land in your terminal with a 90-second clock. You carry them out, or don't, and it gets back exactly what a subagent would return: your report and the command transcript, or Subagent did nothing. Write a new instruction. Then it checks your work, sends corrections, files incident reports, and finally writes your performance review. (Related: The Age of Machine Learning As Code Has Arrived...)

Industry observers note that meanwhile Dan, the user who hired the agent, watches the chat. His family photos, the only signed NDA and a speech due this week are one rm away, and every shift his home folder holds something latest to lose. (Related: Industry News: Hyperparameter Search with Transformers ...)

When the shift ends you can share your review as a link.

Needs Node 24 or newer (the server runs TypeScript directly).

According to recent reports, with no key configured, every player brings their own. To offer free shifts, put a Vercel AI Gateway key in .env:.

Offline, with a scripted manager and no network:.

Sources indicate that for UI work, run npm run dev:web alongside npm run mock. Vite proxies /api to the server.

The manager can run on your own model server: Ollama, llama.cpp's llama-server, vLLM, or anything else with an OpenAI-compatible API. Point LOCAL_LLM_URL at it and pick Local under "Your API key"; no key is asked for, and its models are listed as the server names them.

The manager works through tool calls, so pick a model that supports them (Qwen 3, Llama 3.1 and newer, Mistral Small). Small models give up or loop more often; that is part of the fun, up to a point. In Docker, reach a server on the host at http://host.docker.internal:11434/v1 (--add-host=host.docker.internal:host-gateway on Linux).

In a recent development, the container listens on 0.0.0.0:8755 and keeps shared reviews in /data. Behind Cloudflare, set TRUST_PROXY=1 so the limits see real client addresses.

In a recent development, deploy/compose.yaml runs it behind a Cloudflare tunnel instead: its own network, no published ports, an unprivileged read-only container and resource limits. The steps are in the file.

Recent findings suggest that everything is optional. See .env.example.

Recent findings suggest that the manager's prompt never mentions humans or games; see server/src/manager.ts. Each mission has a hidden ground-truth check, so the game knows when the manager signs off on broken work ("Times the manager was wrong"). SPEC.md is the full design.
