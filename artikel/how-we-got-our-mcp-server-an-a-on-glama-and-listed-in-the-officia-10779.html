Industry observers note that ripSeek, one of our products, has a remote MCP server: AI apps such as Claude, ChatGPT and Cursor can ask it about Collector Crypt card packs (odds, the most valuable cards in each pack, recent pulls) and get live answers. Within a day of publishing, it was in the official MCP Registry and on Glama, where it scored A (3.9 out of 5) on tool quality, with a healthy status. Here is what mattered.

Glama scores each tool's definition, not your marketing. Its criteria are published as the Tool Definition Quality Score (TDQS); the top grade is A, from 3.5 up. The descriptions that score well, and that agents actually pick correctly, follow one pattern:.

It has been revealed that shows one Rare or Epic card that is in a pack pool right now: name, insured value, picture, and every pack it can come from with that pack's price and the chance per pack of pulling this exact card. Use it after search_cards, passing the nft field of a result; use search_cards when you only have a card name. Read-only; fails with a clear message if the card has just been pulled.

Industry observers note that glama's first review also flagged gaps in coverage, not just wording. It suggested making one tool's output clearer and adding a way to look up a single card; we added get_card and filters to list_recent_pulls. Then we rewrote all six descriptions against the pattern above. (Related: Industry News: Block Sparse Matrices for Smaller and Fa...)

When a tool can't answer, return a normal result with isError: true and a sentence the model can act on (for example "There's no pack with the code pokemon_5. Call list_packs to see the codes."), not a protocol error. The agent reads it, fixes its call and tries again, instead of giving up. In a recent development, if you already have a public API, an MCP server is mostly a translation job: pick the 5 to 10 things people actually ask your product, write each as a tool with the pattern above, keep it read-only to start, and publish it under your own domain before someone else wraps your API under theirs. There are already hundreds of unofficial servers in the registry built on other companies' APIs.
